# DEM v2.5.0 LTS Architecture Outline & Technical Roadmap
## Web Application & Graphical Management Dashboard

---

## 1. Executive Vision & Strategy

With the stabilization and official release of **Dev Environment Manager (DEM) v1.0.0** as a CLI framework for **Debian 13 (Trixie)**, DEM enters its next phase of evolution: **DEM v2.5.0 LTS**.

The objective of DEM v2.5.0 LTS is to introduce a web-based graphical dashboard and control panel for environment management while leaving the CLI core engine (`dem.sh` and `lib/`) as the single source of truth.

---

## 2. Core Architectural Principles

1.  **Non-Invasive GUI Layer**: The dashboard acts strictly as an administrative UI layer. It executes underlying DEM commands and inspects system states using existing core functions (`./dem.sh status`, `./dem.sh verify`, `./dem.sh doctor`, `./dem.sh profile apply`, etc.).
2.  **Modern Dark Glassmorphic UI**: Designed using Next.js App Router, React 19, Tailwind CSS v4, Motion (Framer Motion), and Lucide React icons with semi-transparent dark glass surfaces, subtle gradients, and real-time status indicators (`[OK]`, `[WARN]`, `[FAIL]`).
3.  **Real-Time Terminal Streaming**: Module installations and execution logs stream live via Server-Sent Events (SSE) or WebSockets directly to an embedded interactive web terminal component.
4.  **Dry-Run Simulation Safety**: All profile applications and lifecycle triggers allow standard `--dry-run` execution preview before committing system-wide package changes.
5.  **Strict Security & RBAC**: Bound locally by default (`127.0.0.1:3000`) with systemd service isolation, token-based session authentication, and privileged action confirmation.

---

## 3. Technology Stack & Component Architecture

### 3.1 Frontend Stack
*   **Framework**: Next.js 15+ (App Router) & React 19
*   **Language**: TypeScript 5.x
*   **Styling & Design System**: Tailwind CSS v4 with custom Glassmorphism primitives (`backdrop-blur-md`, `bg-slate-900/80`, `border-white/10`)
*   **Animation**: `motion` (Framer Motion)
*   **Icons**: `lucide-react`
*   **State Management**: React Query / SWR for real-time state polling & streaming hooks

### 3.2 Backend API & Integration Layer
*   **API Framework**: Next.js Route Handlers (`app/api/`) / Node.js Process Manager
*   **Execution Bridge**: Node `child_process.spawn` / `exec` wrappers interacting safely with `./dem.sh` CLI commands
*   **Real-time Streaming Engine**: Server-Sent Events (SSE) route handlers streaming stdin/stdout logs during execution
*   **IPC / Daemon Bridge**: Unix Domain Socket or local REST endpoints bound to localhost

---

## 4. Key Features & Dashboard Modules

### 4.1 System Health & Diagnostics Dashboard (`/dashboard`)
*   Visual cards for overall platform status (`Debian 13 Trixie` verification, APT, Systemd, Connectivity).
*   Live diagnostic overview echoing `./dem.sh doctor` with visual badges (`[OK]`, `[WARN]`, `[FAIL]`).
*   Resource usage gauges (CPU, RAM, Disk utilization).

### 4.2 Module & Package Lifecycle Manager (`/modules`)
*   Interactive grid of all 12 architectural package categories (`core`, `docker`, `languages`, `databases-engines`, `tools`, etc.).
*   Status badges displaying real-time module health verified via `verify.sh` routines.
*   Individual action triggers for `Install`, `Configure`, `Verify`, and `Uninstall` with dry-run toggle options.

### 4.3 Profile Orchestration Panel (`/profiles`)
*   Visual card selector for standard profiles (`minimal`, `server`, `desktop`).
*   One-click profile application (`./dem.sh profile apply <profile>`).
*   Comparison tool displaying module diffs across profiles.

### 4.4 Live Process Terminal & Execution Logs (`/terminal`)
*   Web-based terminal viewer rendering stdout/stderr streams during package operations.
*   Log history tab with search and filter capabilities.

## 6. Implementation Roadmap

### Phase 1: Foundation & Design System (Sprint 1-2)
*   Setup Next.js 15 App Router architecture with TypeScript and Tailwind CSS v4.
*   Build Dark Glassmorphic UI component library (Cards, Badges, Terminal Viewers, Action Modals).

### Phase 2: CLI Bridge & API Route Handlers (Sprint 3-4)
*   Develop safe `child_process` wrappers executing `./dem.sh` subcommands safely.
*   Implement SSE route streaming for real-time log execution.

### Phase 3: Module & Profile UI Management (Sprint 5-6)
*   Implement visual category explorer for all 12 DEM package categories.
*   Build profile orchestration interfaces with `--dry-run` simulation toggles.

### Phase 4: System Integration & Security Hardening (Sprint 7-8)
*   Integrate systemd service unit (`dem-dashboard.service`).
*   Incorporate local token authentication and privilege escalation controls.
*   Final testing and validation on Debian 13 (Trixie).
